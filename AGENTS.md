# Gestión Financiera — Codex / Antigravity

Instrucciones para trabajar en este proyecto web. Para usarlas en Antigravity, pide explícitamente que lea este archivo al iniciar la tarea.

1. **Respeta el contexto existente.** Lee las instrucciones aplicables del repositorio y del directorio afectado. Integra estas reglas sin borrar ni sobrescribir a ciegas las anteriores; conserva requisitos específicos y cambios del usuario. Si hay un conflicto que impide avanzar, explica cuál es y consulta solo ese punto.
2. **Lee de forma selectiva.** Localiza archivos por ruta, nombre o símbolo; abre únicamente las secciones pertinentes y sus dependencias necesarias. Amplía la lectura cuando el impacto lo justifique. No recorras todo el repositorio ni releas contenido ya disponible sin motivo.
3. **Mantén el alcance.** Implementa el cambio mínimo suficiente. Evita refactorizaciones, renombrados, reformateos masivos, nuevas dependencias y cambios de configuración ajenos a la tarea. Informa de problemas independientes sin corregirlos por iniciativa propia.
4. **Preserva las fórmulas interconectadas.** Antes de cambiar cálculos, identifica entradas, fórmulas, consumidores y orden de recálculo. Conserva relaciones entre saldos, cuotas, intereses, totales, proyecciones e informes que existan. No reemplaces fórmulas por valores fijos ni dupliques lógica financiera.
5. **Conserva los criterios financieros.** Respeta signos, monedas, unidades, tasas, períodos, precisión y redondeo existentes. Los cambios visuales no deben alterar resultados numéricos. Si la tarea cambia una fórmula, ajusta sus dependencias afectadas y verifica la coherencia; no inventes reglas de negocio para resolver ambigüedades.
6. **Prueba según el riesgo.** Usa los comandos reales del proyecto y ejecuta primero las comprobaciones directamente relacionadas. Para texto o formato, revisa el cambio; para comportamiento, prueba el flujo afectado; para cálculos, comprueba un caso conocido y los límites pertinentes, como cero o redondeo. Añade pruebas cuando protejan comportamiento relevante. Amplía a la suite completa cuando el impacto o las instrucciones existentes lo exijan.
7. **Verifica los cambios relevantes.** Revisa las diferencias finales, los resultados esperados y los consumidores afectados. En cálculos, usa resultados de referencia o una comprobación independiente. Ejecutar un comando sin revisar su resultado no demuestra que el cambio funcione.
8. **Evita herramientas innecesarias.** No hagas capturas, grabaciones, búsquedas web ni exploraciones generales por rutina. Úsalas solo si se solicitan o resuelven una duda concreta necesaria para la tarea. Evita repetir comprobaciones satisfactorias sin cambios nuevos.
9. **No inventes resultados.** No afirmes haber leído archivos, ejecutado pruebas o verificado una pantalla si no lo hiciste. Distingue hechos, supuestos y pendientes. Si una comprobación falla o no puede ejecutarse, explica el motivo y la limitación.
10. **Responde con concisión.** Resume qué cambió, qué verificaste y qué quedó pendiente. Usa español salvo indicación contraria. Omite narración rutinaria, registros extensos y explicaciones que no ayuden a revisar el resultado.
